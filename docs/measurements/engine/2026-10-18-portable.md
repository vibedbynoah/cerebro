# Portable GPU backend (wgpu: Vulkan / DX12 / Metal), 2026-10-18

Machine: Zenbook, i9-12900H, RTX 3070 Ti Laptop (8 GB, driver 32.0.16.1692), Intel Iris Xe (driver
30.0.101.1660), Windows 11. Model: Qwen3-0.6B Q8_0. `examples/greedy.rs ... portable`,
`CEREBRO_PORTABLE_GPU` picks the GPU. Engine commits afb97db .. 455a010.

The portable backend exists for GPUs without CUDA (AMD, Intel, Apple). The NVIDIA card is used here
through Vulkan/DX12 only to test it on a second vendor; on NVIDIA machines the app uses CUDA.

## Correctness
- 64 greedy tokens identical on Iris Xe (DX12, both DXC and FXC) and RTX 3070 Ti (Vulkan and DX12);
  the first 12 equal the CPU's, then a near-tie (activations are f32 on the GPU, q8 on the CPU).
- Through the app with CUDA hidden (`CUDA_VISIBLE_DEVICES=-1`): loads through Vulkan, all 28 layers on
  the GPU, answers "Paris." (ignored test `without_cuda_a_real_model_loads_on_another_graphics_card`).

## Speeds (tok/s; short = 5-token prompt, long = 3k-token prompt)
| Step | GPU | short decode | long prefill | long decode |
|---|---|---|---|---|
| v1: one token per pass | Iris Xe DX12 | 47.7 | 11-16 | - |
| v1 | RTX Vulkan / DX12 | 110 / 137 | 21 | - |
| v2: batched chunks, 4-row kernel only | Iris Xe | 26.3 | (driver reset) | - |
| v2 + kernels timed per GPU at load + clock warm-up | Iris Xe (DXC) | 43-47 | 58 | 18.8 |
| same | RTX Vulkan | 192.5 | 453 | 46 |
| + split attention (interleaved A/B, same session) | RTX Vulkan | 52 vs 54 | 98-120 vs 88 | 31-33 vs 13 |

The last row was measured while the GPU was slower overall (LM Studio and another app held GPU
contexts); old and new builds were alternated so both saw the same conditions.

Kernel timing at load (gate|up matrix of layer 0): Iris Xe picks 1-row kernels (148 us vs 328 us for
the 4-row one), the RTX picks the 4-row kernel for one token after a 0.25 s clock warm-up (without the
warm-up its timings were 2-4x off and it picked badly: decode 134 vs 192 tok/s).

## Intel driver findings
- Vulkan: crashes inside device creation (heap corruption) whatever limits are requested -> Intel on
  Windows defaults to DX12.
- DX12 + FXC (Windows' built-in compiler): 1-row matrix kernels over several tokens hang the GPU
  (driver reset after ~4 s). DXC (shipped with the app, `dxcompiler.dll` only) runs them.
- DX12 + DXC: the split attention kernel hangs at a fixed prompt position, twice; the per-head
  kernel does not. Intel GPUs use per-head attention.
- A single 32-token pass took 4.1 s on the Iris Xe -> Windows reset the driver; submissions are now
  sized to ~0.2 s by measured time.

## Integrated GPU vs the processor
Iris Xe writes at 43-47 tok/s vs ~47 sustained on the i9-12900H (both read the same DDR5), reads a
3k-token prompt at 58 vs 28 tok/s. Integrated graphics is therefore off by default (switch).
