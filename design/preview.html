Cerebro / Design System

Measured, not assumed

A calm instrument for local inference.

Cerebro measures the fastest safe llama.cpp configuration for your exact machine, then runs it.

  • Runs sandboxed
  • Every start integrity-checked
  • Served on loopback only
Get started Read the claims policy
llama.cpp is the open-source program that actually runs an AI model on your CPU or GPU. Cerebro configures and drives it — it doesn't fork or replace it.
Sandboxed, in Cerebro, means two specific things. The model-running process starts inside a Windows Job Object, so when Cerebro stops or exits, Windows ends the whole process tree, including anything the model process spawned. And it starts with a clean environment rebuilt from a short allowlist, so none of Cerebro's own environment variables or secrets reach it. It does not limit which files or network addresses that process can open. The API it serves listens only on loopback.
Integrity-checked means that before every start, Cerebro fingerprints each llama.cpp program file on disk and compares it with the list recorded for the exact build it expects. A changed, missing or extra file stops the launch. It also never inherits a llama-server default setting.
Loopback (127.0.0.1) is an address only your own computer can reach — nothing on your network or the internet can connect to it.
Decode is the phase where the model writes its answer, one token after another. Its speed is what you feel while text streams in.
tok/s (tokens per second) measures how fast a model generates text — a token is roughly a word-piece.

Prefill is the one-time pass where the model reads your whole prompt before it starts writing anything. Its speed mostly matters for long prompts.
Context depth is how much text, in tokens, the model is already holding: your prompt plus the conversation so far. Decode slows as it grows, so a speed measured only at depth 0 overstates real use.
A soak test runs a configuration for minutes, not seconds, and passes only if free graphics memory holds steady or rises across its final third. Short benchmarks on this class of hardware can overstate Mixture-of-Experts throughput by roughly 3×.
A quant (quantization) is how a model's numbers were compressed to fit in memory, for example Q4_K_M. The same model at a different quant runs at a different speed and quality, so a speed figure without its quant is incomplete.

speculative strategies need no draft model

source: docs/CLAIMS.md
Speculative decoding lets llama.cpp guess several tokens ahead and check them all in one pass of the main model. The main model still decides every token, so the output distribution is unchanged; a wrong guess only costs time. A strategy is one way of making those guesses.
A draft model is a second, smaller model that makes those guesses. The five strategies counted here (ngram-simple, ngram-map-k, ngram-map-k4v, ngram-mod, ngram-cache) guess from text already seen instead, so they need no draft model, no extra graphics memory and no second download.
